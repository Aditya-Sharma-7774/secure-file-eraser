# File Eraser X1

Developed a secure, non-recoverable file destruction utility featuring a dynamic local web dashboard (React + Vite) and a Python backend. File Eraser X1 is designed to permanently delete files of any format from the storage level while checking and adapting to specific physical disk constraints (HDD vs. SSD).

## 🚀 Features

- **Colorful Local Web Dashboard**: A vibrant glassmorphism interface (cyan → violet → pink gradients), animated accents, custom sliders, live stat tiles, and a two-mode layout (Shred / Free-space wipe).
- **Multi-File & Folder Queue**: Add many files or an entire folder; each file is processed in turn with a per-file status pill and progress bar.
- **Physical Drive Media Detection**: Queries physical disks on Windows (via PowerShell) to classify each file's volume as **SSD** or **HDD**.
- **Hardware-Specific Sanitization**:
  - **HDD Mode**: Multi-pass overwrite cycles (ones `0xFF`, zeroes `0x00`, and per-byte OS-cryptorandom blocks from `os.urandom`) to counter magnetic signature recovery.
  - **SSD Mode**: Zero-fills logical blocks, then runs a **native TRIM** (`Optimize-Volume -ReTrim`) so the flash controller purges unmapped pages — then renames, truncates, and unlinks.
- **Binary Footprint Inspector**: Inspect any file before wiping in three views — **Hex**, **Binary** (8-bit), and **Strings** (printable-ASCII scan that reveals hidden/embedded messages) — with pagination across the whole file, plus a post-wipe "Wiped" read-back.
- **Free-Space Wipe**: Scrubs unallocated space on a chosen drive with the native Windows `cipher /w` (0x00, 0xFF, random) so previously deleted files can't be carved back.
- **Erasure Certificate**: Exports a **PDF or JSON** proof of deletion — filename, pre-wipe **SHA-256** hash, method, pass count, verification result, and timestamp.
- **Live Progress**: Real-time **MB/s throughput**, current pass number, and estimated time remaining.
- **Cancel / Halt**: A cancel button signals the server to stop safely and reports how many files/passes completed.
- **Type-to-Confirm Guard**: Destructive actions require typing the file name (or `ERASE ALL`) to unlock — no accidental single-click wipes.
- **Data Erasure Verification**: Reads back sectors before deletion to confirm the write and detect controller redirection.
- **Zero-Dependency Python Backend**: Built entirely on the standard library (`http.server`, `tkinter`, `subprocess`, `hashlib`) — no pip installs. Certificates (including the PDF) are generated by hand.

```

    ├── src/

    │   ├── components/
```

### Backend API

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/browse` | POST | Native file/files/folder picker (tkinter) |
| `/api/file-info` | GET | Size, drive, SSD/HDD media type |
| `/api/hex-data` | GET | Paginated hex dump (offset/length) |
| `/api/strings` | GET | Printable-ASCII scan (hidden-message finder) |
| `/api/drives` | GET | Drive list with free/used/total |
| `/api/erase` | POST | SSE-streamed multi-file wipe |
| `/api/wipe-free-space` | POST | SSE-streamed native `cipher /w` |
| `/api/cancel` | POST | Halt an in-flight job by `job_id` |
| `/api/certificate` | POST | Download erasure proof (PDF or JSON) |

## ⚙️ Installation & Usage

### Prerequisites
- Python 3.x installed and added to your system path.
- Node.js (with npm) installed to compile the React frontend.

### Running the Application

1. **Clone the Repository**:
   ```bash
   git clone https://github.com/your-username/secure-file-eraser.git
   cd secure-file-eraser
   ```

2. **Automated Launch**:
   Simply double-click the **`run.bat`** file or execute it in your terminal:
   ```cmd
   run.bat
   ```
   *This script automatically checks and builds the React frontend static pages, starts the local Python backend, and launches the client in your default web browser at `http://127.0.0.1:8999/`.*

3. **Manual Backend Start**:
   If the frontend is already compiled, you can start the backend directly using Python:
   ```bash
   python server.py
   ```

## 🔬 Deletion Verification Flow

1. **Analyzing & Pre-read**: The app scans the file, queries disk properties, and reads the first 512 bytes to render in the "Original Data" hex tab.
2. **Physical Write Overwrite**: Data is written directly using 1MB chunks and flushed physical block buffers using `os.fsync`.
3. **Double-Check Reading**: The backend re-reads the disk blocks, comparing them to verify the signature of the write cycle before deleting. The updated state is shown in the "Wiped Data" hex tab.
4. **Metadata Obfuscation**: The file is renamed to a random string, truncated to 0 bytes, and unlinked from the directory indices using `os.remove`.
